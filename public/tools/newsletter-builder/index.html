📊 Content Structure Recommendation

Based on educational type and practitioners audience:

  1. Hook (1-2 sentences): Draw them in
  2. Context (1 paragraph): Why this matters now
  3. Main content (3-5 points): The meat
  4. Summary (1 paragraph): Key takeaway
  5. CTA (1 line): What to do next

Who is Newsletter Builder not ideal for?

  • Anyone who cannot give the required inputs (Topic, CTA goal); the answer is built only from them.
  • Teams that want finished, on-brand copy: each tool returns a structured draft to edit, with placeholders where your inputs gave no fact.
  • Anyone who needs research or quotes gathered for them: the tools look nothing up; they work from the story and facts you give, and anything they add themselves is marked as an example, a suggestion or a placeholder.

How do I use Newsletter Builder from Claude?

Connect CRAFT Content once (see Connect), then ask in plain words. A prompt built from the tested example:

Use CRAFT Content's Newsletter Builder tool. topic: Onboarding checklists for SaaS teams; cta goal: register for our onboarding webinar; audience segment: practitioners; newsletter type: educational; tone: conversational.

MCP tool name: newsletter_builder. REST: POST https://craft-content.gtmhelix.com/api/tools/newsletter_builder with this JSON body (see Docs):

{
  "input": {
    "topic": "Onboarding checklists for SaaS teams",
    "cta_goal": "register for our onboarding webinar",
    "audience_segment": "practitioners",
    "newsletter_type": "educational",
    "tone": "conversational"
  }
}

How does Newsletter Builder work?

It applies fixed rules in the CRAFT Content code to the inputs above and returns text. It does not call an AI model, does not look anything up, and does not store what you type. The web form and the MCP server call the same tool code, so the same input gives the same answer in both.
