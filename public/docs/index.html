For developers

CRAFT Content docs

For developers and marketing operations teams. The decision: how to call CRAFT Content from your own code or assistant.

Connect to the 9 MCP tools, check their input fields or call the REST API behind the web forms.

Pick a tool

By Shashwat Ghosh, Co-Founder and Fractional CMO, Helix GTM Consulting · Last updated 15 November 2026

Try these prompts

  1. Use CRAFT Content to draft a customer case study. Customer: a food delivery company. Our product: an AI support agent for help desks, sold as an annual subscription. Challenge: a ticket backlog growing faster than the support team could hire. Solution: AI agents that resolve refund and order-status tickets in the help desk, with human approval for refunds. Results: 45% of tickets resolved without a human in 60 days. Mode: full.
  2. Build a practitioner newsletter with CRAFT Content about AI agents in customer support. Call to action: register for our support automation webinar.
  3. Write a 45-minute educational webinar script with CRAFT Content on AI agents that resolve support tickets safely, for support leaders at consumer apps and SaaS companies.
  4. Review this landing page copy with CRAFT Content and suggest improvements: 'our product leverages cutting-edge AI to empower support teams to deliver best-in-class experiences at scale.'

MCP server

  • Address: https://craft-content.gtmhelix.com/mcp (Streamable HTTP, stateless, JSON responses). GET returns 405 by design.
  • Authentication: none. Every tool is marked read-only (readOnlyHint: true, destructiveHint: false) and has a title.
  • Rate limit: 300 requests per minute per IP address. Server: craft-content-mcp version 2.2.24.
  • Limits: 262,144 bytes per call; text fields up to 4,000 characters, except the document fields interview_notes (Case Study Generator), source_content (Content Repurposer) and content (CRAFT Content Improver), which take up to 100,000; one call per request (no batches). A call over a limit is refused before the tool runs.
  • Local stdio: npx -y @shashwatgtmalpha/craft-content-mcp. Latest npm version on 15 November 2026: 2.2.22.

REST API (used by the web forms)

Send POST https://craft-content.gtmhelix.com/api/tools/<tool name> with a JSON body {"input": {...}}. The answer is JSON: {"ok": true, "tool": "...", "title": "...", "text": "..."}, where text is the same Markdown the MCP tool returns. The endpoint calls the same server code as the MCP address.

Terminal
curl -s -X POST https://craft-content.gtmhelix.com/api/tools/case_study_generator \
  -H "Content-Type: application/json" \
  -d '{"input": {"customer_name": "a food delivery company", "your_product": "an AI support agent for help desks, sold as an annual subscription", "customer_industry": "Food delivery", "mode": "full", "challenge": "A ticket backlog growing faster than the support team could hire", "solution": "AI agents that resolve refund and order-status tickets inside the help desk, with human approval for refunds", "results": "45% of tickets resolved without a human in 60 days; first response time down from 6 hours to 2 minutes"}}'
  • Errors: 400 with errors (missing or invalid fields), 404 for an unknown tool, 405 for methods other than POST, 413 above 32,000 bytes, 422 when the tool itself refuses the input (ok is false and error holds the tool's message), 429 when the rate limit is reached, 500 if the tool fails.
  • Limits: 30 requests per minute per IP address; the whole request up to 32,000 bytes; top level text fields up to 6,000 characters and top level lists up to 50 items.
  • Forms without JavaScript post application/x-www-form-urlencoded and get an HTML page back.
  • Inputs and answers are not stored, and the input is not logged (see Privacy).

Case Study Generator

case_study_generator

Helps you turn a customer result into a case study, built from the customer name, your product and the challenge, solution and results you give (mode full), or an interview kit to collect them (mode discovery). Optional customer industry, quote, interview notes and business model fit the wording to the customer. Returns a headline, the story with each result you list, a customer quote, social and email copy, and sector notes when the sector can be read from your text. A bracket marks anything you did not give. Ask whether written customer approval covers the exact material and intended use.

FieldTypeRequiredAllowed valuesMeaning
customer_namestringyesCustomer or company name
customer_industrystringnoThe customer's industry, used for context
modestringnofull, discoveryfull builds the case study and needs the challenge, solution and results; discovery returns interview questions for collecting them
interview_notesstringnoOptional: raw interview notes or a transcript. In full mode they fill a missing challenge, solution or results; the answer says they were not used when you gave all three
challengestringnoThe customer's challenge or problem (needed in full mode)
solutionstringnoHow your product solved it (needed in full mode)
resultsstringnoMeasurable outcomes, one per line or per semicolon (needed in full mode)
customer_quotestringnoOptional: a direct quote from the customer
your_productstringyesYour product or service name
business_modelstringnosaas, services, connectivity, transactions, marketplace, hardware_software, investmentOptional: how you charge, so the advice fits it. If omitted, it is read from your text and the answer says how.
your_sectorstringnologistics_tech, fintech, saas, vertical_saas, ai_native, ites, telecom, software, cybersecurity, otherOptional: your company's own industry (not your customers'). When given, it decides the sector notes; when left out, the tool reads it from your words and stays neutral if they are unclear.
publication_approvalstringnoapproved, not_approved, unknownOptional confirmed written approval for this exact customer name, figures, quote and intended use. Ask before publication. A draft cannot grant customer permission.

How to read the answer

Both the MCP server and the REST endpoint return the same structured Markdown text for a given input object, or, from the REST endpoint, an HTTP 400 error listing any missing or invalid fields or a 422 when the tool itself refuses the input. Inside the returned Markdown, bracketed placeholders mark missing facts and any unprovided benchmark is labelled as an example figure.

What to do next

  • Founder: Test a tool call with the example cURL request or MCP URL using your own product and customer facts.
  • CEO: Review the tool reference to see which required and optional fields your team should supply for complete drafts.
  • CMO: Use the input schemas to standardize the briefs your team feeds into Case Study Generator, Newsletter Builder, and Sales Enablement Content.
  • CRO: Check the fields for Sales Enablement Content and Case Study Generator so sellers pass complete deal and competitor context.
  • Demand generation head: Pass your real audience, topic, and channel parameters into Webinar Script, Newsletter Builder, and Content Repurposer.
