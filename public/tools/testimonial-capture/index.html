Who is Testimonial Capture not ideal for?

  • Anyone who cannot give the required inputs (Customer name, Customer company, Success story, Testimonial type); the answer is built only from them.
  • Teams that want finished, on-brand copy: each tool returns a structured draft to edit, with placeholders where your inputs gave no fact.
  • Anyone who needs research or quotes gathered for them: the tools look nothing up and use only the story and facts you give.

How do I use Testimonial Capture from Claude?

Connect CRAFT Content once (see Connect), then ask in plain words. A prompt built from the tested example:

Use CRAFT Content's Testimonial Capture tool. customer name: Sam Example (fictional); customer company: Northwind Clinics; success story: Cut no-shows by 30% with automated reminders; testimonial type: written quote; customer role: Operations Director.

MCP tool name: testimonial_capture. REST: POST https://craft-content.gtmhelix.com/api/tools/testimonial_capture with this JSON body (see Docs):

{
  "input": {
    "customer_name": "Sam Example (fictional)",
    "customer_company": "Northwind Clinics",
    "success_story": "Cut no-shows by 30% with automated reminders",
    "testimonial_type": "written_quote",
    "customer_role": "Operations Director"
  }
}

How does Testimonial Capture work?

It applies fixed rules in the CRAFT Content code to the inputs above and returns text. It does not call an AI model, does not look anything up, and does not store what you type. The web form and the MCP server call the same tool code, so the same input gives the same answer in both.
